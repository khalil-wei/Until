# HarmonyOS 2.1.1 留存激活与卡片体验改造方案

## 1. 背景与结论

`待到 / Until` 的核心价值不是要求用户每天打开 App，而是让重要日期通过本地提醒和服务卡片持续可见。HarmonyOS `2.1.1` 在新增表单中默认选择“提前 1 天提醒”，并在首次保存后单独承接服务卡片，形成一条不依赖服务器和线上埋点的本地激活路径：

```text
创建至少一个事件
        +
开启至少一个提醒或添加至少一张服务卡片
        =
完成基础激活
```

本方案是场景化激活引导，不是强制的新手教程。用户在每一步都可以跳过，已经完成对应能力的用户不会再次收到同类引导。

## 2. 版本目标

HarmonyOS `2.1.1` 只解决以下问题：

- 空数据用户能在首次会话快速创建第一个重要日子。
- 用户在新增表单中完成提醒选择，第一个事件保存成功后再理解并选择服务卡片。
- 日历权限只在用户主动开启同步时请求；通知权限在用户保存仍开启提醒的事件后请求。
- 已有事件但未开启回访渠道的用户能看到安静、可关闭的下一步提示。
- App 冷启动和回到前台时能校准事件日期、提醒和服务卡片。
- 已添加的服务卡片在事件新增、编辑和删除后能更稳定地显示最新数据，并在中、大尺寸中完整呈现更多近期日子。
- 所有旅程状态只保存在本机，不上传用户行为或倒计时内容。

本版本不包含：

- 在线埋点、账号、服务器或云同步。
- 自动读取全部系统日历或联系人。
- 多阶段组合提醒、自定义提醒时刻。
- 分享图片、社交关系或运营推送。
- 新增彩蛋和大规模视觉重构。

## 3. 设计原则

### 3.1 先行动，后解释

首次打开直接提供“添加生日 / 添加纪念日 / 添加其他日子”，不展示多页轮播教程，不在用户表达意图前请求日历或通知权限。

### 3.2 每次只提示一个下一步

空数据时只引导创建；提醒在新增表单中完成选择；保存成功后只承接服务卡片；完成任意回访渠道后结束基础引导。

### 3.3 本地功能优先

事件必须先可靠保存到本地。提醒、服务卡片和日历同步失败不得回滚本地事件，也不得阻止用户返回首页。

### 3.4 可跳过、可恢复、不过度打扰

成功引导允许“暂时不用”。首页任务卡不是模态弹窗，并遵守本地冷却时间；用户关闭后不在每次启动重复出现。

### 3.5 升级用户不重新过新手流程

从 `2.0.2` 升级且已有事件的用户直接进入事件列表。只有在没有任何提醒、没有服务卡片且未主动关闭引导时，首页才显示非模态任务卡；不会自动弹出首次保存引导。

## 4. 激活状态机

| 状态 | 判定 | 页面行为 | 下一状态 |
| --- | --- | --- | --- |
| `empty` | 没有真实事件 | 展示激活型空首页，隐藏搜索和分类 | 保存首个事件后进入 `eventOnly` |
| `eventOnly` | 至少一个事件，且无可用提醒、无服务卡片 | 展示成功承接或首页任务卡 | 开启提醒或添加卡片后进入 `activated` |
| `activated` | 至少一个事件，且存在已授权的提醒或服务卡片 | 不展示激活引导 | 保持正常使用 |
| `deferred` | 用户主动跳过或关闭任务卡 | 正常首页；冷却期内不提示 | 用户主动进入入口或冷却到期后可重新进入 `eventOnly` |

基础激活以“事件 + 任一回访渠道”为准，不要求用户同时开启通知和服务卡片。第二个事件属于后续增强，不作为强制完成条件。

## 5. 本地状态与数据来源

### 5.1 直接从业务数据推导

- `hasEvents`：事件仓库中至少存在一个非演示事件。
- `hasSelectedReminder`：至少一个事件的 `reminderLeadTime` 不是 `None`。
- `hasEnabledReminder`：存在已选择提醒的事件，且系统通知权限可用。
- `hasAddedCard`：服务卡片实例仓库中至少存在一个有效 Form ID。

### 5.2 本地旅程状态

新增独立的 `UserJourneyStore`，只保存以下不敏感状态：

| 字段 | 用途 |
| --- | --- |
| `hasSeenFirstSaveGuide` | 防止首次保存后的服务卡片引导重复弹出 |
| `activationCardDismissedAt` | 控制再次提示的本地冷却时间 |
| `lastKnownCardCount` | 在无法即时查询桌面宿主时提供本地降级判断 |

旅程状态与倒计时事件分库存储，不包含事件标题、日期、备注、系统日历 ID 或通知内容，也不通过网络上传。

## 6. 页面与交互流程

### 6.1 激活型空首页

无事件时隐藏右上角普通新增按钮、搜索框和分类筛选，展示：

- 标题：“把重要日子放在眼前”。
- 说明：“先选一种日子，保存后可以添加到桌面随时查看”。
- 三个快捷入口：“记录一个生日”“记录一个纪念日”“记录其他日子”。
- 服务卡片价值说明。

快捷入口打开新增页时携带预选分类。未携带分类时保持普通新增行为。

### 6.2 新增表单

首要信息为名称、类型和日期；提醒、备注与系统日历同步保持可用，但降低视觉优先级。

HarmonyOS `2.1.1` 的新增默认值：

- 类型由入口决定，普通入口默认生日。
- 日期必须由用户明确确认；不以“今天”作为无感默认提交值。
- 提醒默认选择“提前 1 天”并放在第一个选项，不附加“推荐”字样；用户可在保存前改为其他提前量或“不提醒”。
- 系统日历同步默认关闭。

点击日历同步开关只表达用户意图；实际权限请求不得早于这一动作。通知权限只在事件以非“不提醒”状态保存后请求。

### 6.3 首次保存后的服务卡片承接

首个事件在没有现存服务卡片时，本地保存成功后展示一次成功承接。提醒只在新增表单和权限结果中处理，承接层不再重复展示提醒状态或提醒按钮，只保留桌面卡片引导：

```text
已添加“事件名称”
距离这个日子还有 N 天

[添加到桌面]
[暂时不用]
```

规则：

- 本地事件写入成功即决定保存结果；后续日历同步、通知授权或提醒排程失败都不回滚事件。
- 默认提醒随事件保存后请求通知权限；若用户选择“不提醒”则不请求，通知结果不阻断服务卡片引导。
- 用户选择服务卡片时打开系统卡片管理页；当前 SDK 或设备不支持时展示简短的手工添加步骤。
- 用户选择“暂时不用”后返回首页并进入 `deferred`，不立刻再次弹出。
- 编辑已有事件不展示首次保存引导。

### 6.4 首页任务卡

用户已有事件但未完成基础激活时，在事件列表顶部展示非模态任务卡：

```text
让这个日子主动回来
[开启提醒] [添加到桌面]
```

点击未完成项进入对应动作。任务卡允许关闭，并遵守 7 天冷却；一旦完成基础激活立即隐藏。

### 6.5 权限时机

| 权限 | 请求时机 | 拒绝后的行为 |
| --- | --- | --- |
| 通知 | 事件以非“不提醒”状态保存后 | 保留事件与提醒选择，提示可在设置中开启；服务卡片引导继续展示，不反复弹窗 |
| 日历写入 | 用户主动打开同步并执行保存/同步时 | 保留本地事件，将来源降级为本地并提示同步未完成 |
| 日历读取 | 本版本不在首启主动请求 | 不影响任何本地能力 |

## 7. 提醒与卡片校准

新增统一的留存协调流程，在 App 冷启动、回到前台和事件变更后执行：

1. 从事件仓库加载最新数据。
2. 根据当前本地日期重新计算每个事件的下一次发生日期。
3. 检查通知权限；未授权时不发起无上下文的权限请求。
4. 对已开启提醒的事件优先预排未来两次年度提醒，清理删除或关闭后的提醒；超过系统 30 条有效提醒上限时按触发时间保留最近 30 条。
5. 刷新已登记的服务卡片实例。

提醒校准必须幂等。相同事件、相同发生日期和相同提前量不得产生重复提醒。若平台 API 只能整体取消，应保证取消与重建在同一串行队列中完成，并在真机验证重启、升级、跨日与跨年行为。

## 9. 无线上埋点时的验证方式

本版本不新增 Analytics SDK、服务器或自定义事件上报。效果评估使用华为应用市场已有的版本级聚合数据：

- `2.0.2` 与 `2.1.1` 的新增用户 D1、D7、D30。
- 升级用户和新安装用户的崩溃、ANR、卸载与评分变化。
- 应用评论中与“不会用、提醒没到、卡片找不到、权限”相关的关键词。

由于没有自定义漏斗，本版本不能精确区分各步骤的独立贡献。因此必须控制改造范围，并把 `2.1.1` 视为完整激活闭环实验；若 D7 没有改善，再为后续版本建设最小 Serverless 漏斗。

## 10. 升级与异常处理

- `2.0.2` 已有事件必须无损保留，事件编码格式不因旅程状态改变。
- 旅程状态缺失时使用安全默认值，不阻塞首页。
- 服务卡片实例读取失败时按“未确认已添加”处理，但不强制弹窗。
- 通知权限拒绝、系统卡片加桌失败、日历同步失败均不回滚事件。
- 用户删除最后一个事件后回到 `empty`；旅程冷却仍保留，避免重复模态提示。
- 搜索或分类导致列表暂时为空时展示“无匹配结果”，不能误进入首次激活空状态。
- 英文、字体放大、深色模式、小屏和减少动态效果均需覆盖。

## 11. 验收标准

### 首次使用

- 全新安装进入空首页时不请求日历或通知权限。
- 无事件时不展示搜索和分类，三个快捷新增入口可用。
- 快捷新增正确预选生日、纪念日或自定义分类。
- 首个事件可只依赖本地存储完成保存。
- 首次保存后的服务卡片承接只展示一次，用户可以跳过。

### 激活与打扰控制

- 已有事件且无提醒/卡片时可见首页任务卡。
- 开启任一提醒或添加任一服务卡片后任务卡消失。
- 主动关闭任务卡后 7 天内不再次主动展示。
- `2.0.2` 升级用户不会自动弹出首次保存承接。

### 权限与降级

- 通知权限只在事件保留非“不提醒”状态并保存后请求；选择“不提醒”不得请求。
- 日历权限只在用户明确选择同步后请求。
- 任一权限拒绝都不影响本地事件保存、查看、编辑和删除。
- 无法打开系统卡片管理页时提供可执行的手工添加说明。

### 提醒与卡片

- App 冷启动和回到前台后能补排有效提醒且不产生重复项。
- 编辑提醒提前量后旧提醒被替换，删除事件后提醒被取消。
- 已有服务卡片在事件变化和跨日后刷新。
- 从服务卡片进入新增或详情仍保持正确路由。

### 构建与发布

- HarmonyOS Debug 构建和单元测试通过。
- `2.0.2` 到 `2.1.1` 真机升级后事件、提醒关联和卡片实例保持完整。
- 先进行小范围发布并观察完整 D7 周期，稳定后再全量。
