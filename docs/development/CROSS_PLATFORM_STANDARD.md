# 待到多端开发标准

本文是 iOS、HarmonyOS、Android 的统一开发标准，集中维护功能完成定义、UI、数据、文案、测试和发布要求。当前能力状态只以[三端功能矩阵](../../packages/contract/feature-matrix.md)为准，产品规则与数据字段见[跨平台产品契约](../../packages/contract/README.md)。

## 1. 仓库与职责边界

```text
apps/       平台原生工程
packages/   共享契约、测试样例、本地化预留源和设计素材
docs/       产品、开发和发布文档
scripts/    校验、资源生成和发布辅助脚本
```

- 页面、导航和系统能力分别使用 SwiftUI、ArkUI、Jetpack Compose 等原生技术实现。
- 跨端共享产品规则、数据语义、测试样例、固定术语、设计令牌和验收要求，不共享运行时代码。
- 签名材料、IDE 用户状态和本机配置不得提交到仓库。
- 仅一个平台支持的能力必须在功能矩阵中标记为“平台特性”。

变更流程：先更新 `packages/contract/`，再补共享样例和产品文档，随后分别实现三端；完成测试和真机验收后更新功能矩阵。

## 2. 功能完成定义

| 功能域 | 三端完成定义 | 允许的平台差异 |
| --- | --- | --- |
| 首页 | 使用持久化数据；支持搜索、分类、今天/即将到来分组和真实刷新。 | 控件、导航和刷新入口遵循平台习惯。 |
| 事件 | 新增、编辑、详情和删除使用稳定 ID；保存后首页、详情和组件同步刷新。 | 原生日期选择器与路由形式可不同。 |
| 删除 | 操作前确认，并按来源说明仅删除本地记录、关联日历事件或两者。 | iOS 可隐藏/恢复导入事件；Android、HarmonyOS 不纳入该能力。 |
| 日期 | 公历、农历、闰月和 2 月 29 日规则一致；排序使用标准化后的下一次发生日期。 | 农历选择和格式化使用平台原生实现。 |
| 日历 | 权限拒绝不阻塞本地能力；创建、更新、删除使用平台关联 ID。 | EventKit、Calendar Kit、Calendar Provider 分别实现。 |
| 提醒 | 支持当天及提前 1/3/7 天；修改或删除后取消旧任务并重排。 | 权限、后台策略和送达保障按平台处理。 |
| 组件 | 使用真实数据；小尺寸 1 条、中尺寸 3 条；事件变化和跨日后刷新。 | 可用尺寸、锁屏和配置能力按平台支持。 |
| 国际化 | 简体中文和英文不混用；日期遵循系统区域格式。 | 系统权限弹窗可不同，应用说明语义必须一致。 |
| 无障碍 | 关键控件有标签和足够点击区域，适配字体放大与减少动态效果。 | 使用平台原生无障碍 API。 |
| 彩蛋 | 不改变事件、排序、提醒、日历或组件状态，不播放声音。 | 动效细节可按平台能力调整。 |

### 页面状态

| 状态 | 要求 |
| --- | --- |
| 加载中 | 轻量展示，不阻塞导航。 |
| 无数据 | 显示空状态和新增入口。 |
| 保存中 | 禁止重复提交。 |
| 同步中 | 保留已有本地数据。 |
| 部分失败 | 说明日历或提醒失败，并提供可执行的处理建议。 |
| 权限被拒绝 | 保留本地功能，并提供重新授权路径。 |

## 3. UI 与交互

首页顺序为标题栏、搜索、分类、权限或异常状态、今天分组、即将到来分组、空状态/事件列表。详情页展示持久化数据重新计算后的事件摘要、类型、日期、来源、日历、提醒、备注及操作。编辑页按标题、类型、历法、日期、备注、提醒和日历同步排列，保存入口不得被键盘永久遮挡。

事件卡片保持“类型标识、标题与日期、倒计时结果”三层信息优先级。标题最多两行，倒计时不得被挤压；超过 999 天时紧凑区域中文显示“遥遥有期”、英文显示 `1000+ days`，详情和无障碍文案仍显示准确天数。

共享设计基线：

| 类别 | 令牌 | 基准值 |
| --- | --- | --- |
| 颜色 | `background` | `#F4F7F5` |
| 颜色 | `surface` | `#FFFFFF` |
| 颜色 | `primary` | `#08A88F` |
| 颜色 | `text` | `#1F2926` |
| 颜色 | `secondaryText` | `#6F7B77` |
| 颜色 | `divider` | `#E2EAE6` |
| 颜色 | `danger` | `#D94A5B` |
| 圆角 | `card` | `16dp/pt` 基线 |
| 圆角 | `control` | `12dp/pt` |
| 间距 | `page` | `20dp/pt` |
| 点击区域 | `minimum` | `44dp/pt` |

各端实际主题值如与共享基线不同，应在平台文档中记录。禁止在单个页面临时创建另一套产品颜色或间距。

动画应短暂、可中断，并在系统关闭动画时保持功能可用。刷新必须对应真实数据读取；保存、删除、权限、同步成功和失败均需提供明确反馈。不得出现假刷新、重复提交、只更新当前页面或向用户展示异常堆栈。

## 4. 数据与系统能力

- UI 依赖标准化事件模型，不直接持有系统日历对象。
- 年度日期按 `originalDate` 重算；已过日期进入下一年，2 月 29 日跳到下一个有效闰年。
- 保存顺序为输入校验、本地写入、日历关联处理、日期与排序重算、消费者刷新。
- 系统日历失败不得回滚已成功的本地保存，但必须记录同步状态并提示用户。
- 日历读取、写入和删除通过关联 ID 完成，不使用标题、日期或列表索引猜测目标事件。
- 提醒设置变化时先取消旧任务，再创建新任务；无提醒权限时保留事件。
- 组件数据来自持久化存储，不使用演示数据；系统重建组件时重新读取。

## 5. 文案与国际化

文案分为共享产品文案、平台系统说明和开发诊断信息：

- 生成链路落地前，三端用户文案由平台资源人工对照维护；落地后统一进入 `packages/localization/source/`。
- 权限用途等应用说明必须统一语义；系统自带控件文案遵循平台。
- 开发诊断只允许出现在 Debug 日志，不得进入生产 UI、Toast 或商店截图。

| 语义 | 简体中文 | English |
| --- | --- | --- |
| 产品名 | 待到 | Until |
| 生日 | 生日 | Birthday |
| 纪念日 | 纪念日 | Anniversary |
| 自定义 | 自定义 | Custom |
| 公历 | 公历 | Gregorian |
| 农历 | 农历 | Lunar |
| 不提醒 | 不提醒 | No reminder |
| 当天提醒 | 当天提醒 | Today |
| 提前 1/3/7 天 | 提前 1/3/7 天 | 1/3/7 days before |
| 即将到来 | 即将到来 | Upcoming |
| 暂无日程 | 暂无日程 | No events |

中文使用简体中文与全角标点；英文使用自然的产品英语和 Sentence case。错误提示说明结果和下一步，不暴露包名、权限枚举或系统 API 名称。缺失翻译必须在校验阶段暴露，不得静默回退到另一种用户语言。

## 6. 测试、隐私与发布

测试分层：

1. 使用 `packages/test-fixtures/` 覆盖年度日期、农历、闰日、排序、去重、提醒和彩蛋规则。
2. 各平台测试存储、模型转换、日历、提醒和组件映射。
3. 真机覆盖首次启动、空数据、授权/拒绝/重新授权、增删改查、刷新、语言、字体、键盘、农历、日历、提醒和组件。

发布前必须确认：

- 功能矩阵与实际候选包一致，共享样例和平台测试通过。
- 至少完成一轮真机回归，没有测试数据、调试提示或未完成入口。
- 模块权限、隐私政策和商店声明逐项一致；拒绝权限后核心本地功能仍可用。
- Debug 包不用于商店；Release/Production 使用仓库外正式签名。
- 包名、版本号、构建号、证书、中文/英文文案、截图和版本说明一致。

只有满足以上条件，功能才能在矩阵中标记为“已支持”，候选包才能提交应用市场。
