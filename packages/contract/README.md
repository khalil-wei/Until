# 跨平台产品契约

本文集中记录 iOS、HarmonyOS、Android 共用的产品规则、数据模型、平台边界和验收要求。当前实现状态只以[三端功能矩阵](feature-matrix.md)为准；开发完成定义见[多端开发标准](../../docs/development/CROSS_PLATFORM_STANDARD.md)。

本目录不包含运行时代码。调整产品行为时，先更新本文与功能矩阵，再修改平台实现、共享样例和发布文档。

## 1. 产品规则

`待到 / Until` 管理重要年度日期，并将下一次发生日期显示为倒计时。

- 事件按距离下一次发生日期的天数升序排列，今天优先显示。
- 支持生日、纪念日和自定义类型，以及公历、农历和 2 月 29 日规则。
- App 创建的日历事件可从 App 移除，并在平台支持时同步删除系统日历事件。
- 小组件和服务卡片只展示最近的真实事件，不使用演示数据。
- 三端使用独立本地存储，不提供跨设备云同步。

### 平台特性

- iOS 可隐藏导入的系统日历事件而不删除原日程，并提供恢复入口。
- 隐藏/恢复不是三端统一能力：Android 不提供；HarmonyOS 不对外提供，现有遗留入口待清理。
- Android 新增按月、按周重复；当前 iOS 与 HarmonyOS 保持按年行为。`recurrence` 缺省为 `yearly`，旧事件不自动改变重复规则。
- Android 导入日历按源事件的 RRULE 与原始开始日期识别可完整表达的年/月/周规则。每两周、多星期、次数或截止日期限制、额外/排除日期及单次例外等复杂规则不导入、不回写，并提示跳过数量。旧导入项在刷新时校正重复规则、保留内部 ID 与提醒；查询失败或缺少窗口内实例不清空旧记录，明确发现不支持的旧导入项退出当前导入列表，但不删除系统日历。只修改标题或备注时不重写重复规则、日期、时间和时区；保存前重新读取源规则，无法核实或已变为复杂规则时阻止保存。
- 按月以所选历法的日数重复，没有该日的月份跳过；农历闰月作为独立月份参与重复。按周从原始日期起每 7 个本地日期重复，与历法无关。未来原始日期为首次发生日期，不提前生成实例。
- 除已记录的平台特性外，平台差异只能改变实现方式，不能改变用户可见语义。

### 低频彩蛋

- 剩余恰好 42 或 365 天时，可在所有支持语言中显示辅助文案；520 天文案仅在中文环境显示。
- 特别数字文案不替换准确倒计时。
- 非空列表可在本地 00:00–05:00 显示深夜来信；每 30 天最多一次，不发送通知、不触发后台任务。
- 大于 999 天时，详情页长按 1.5 秒可展示星点汇聚和中央准确天数；紧凑徽章不变，效果自动重置。
- 到达当天首次打开详情可显示分类庆祝；同一事件同一本地日期最多自动触发一次，当前详情页可手动重播一次。
- 庆祝不播放声音、不阻塞交互，并适配系统“减少动态效果”。
- 彩蛋不得改变事件、排序、提醒、日历或组件/卡片状态。

## 2. 数据模型

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | UUID/string | 稳定内部标识。 |
| `title` | string | 必填事件名称。 |
| `nextOccurrence` | date/time | 用于显示和排序的下一次发生日期。 |
| `originalDate` | date/time | 用于重算重复日期的原始日期，同时作为首次发生日期。 |
| `category` | enum | `birthday`、`anniversary`、`custom`。 |
| `dateCalendar` | enum | `gregorian`、`lunar`。 |
| `recurrence` | enum | `yearly`、`monthly`、`weekly`；Android 已接入，旧记录缺省为 `yearly`。 |
| `source` | enum | `local`、`appCalendar`、`importedCalendar`。 |
| `calendarEventID` | string/null | 平台日历事件标识。 |
| `calendarItemID` | string/null | 可用时保存的平台稳定日历项标识。 |
| `notes` | string/null | 可选备注。 |
| `reminderLeadTime` | enum | `none`、`sameDay`、`oneDay`、`threeDays`、`sevenDays`。 |

iOS 可额外保存 `isIgnored` 以隐藏/恢复导入事件。该字段不是跨平台事件契约，Android 与 HarmonyOS 不得据此提供用户可见能力。各端可使用本地字段名和存储格式；共享测试样例或数据交换使用上表字段名。

## 3. 平台能力边界

### iOS

- SwiftUI App、WidgetKit 桌面/锁屏组件、EventKit 日历。
- App 与 Widget 通过 App Group UserDefaults 共享数据。
- 最低部署版本 iOS 17.0。
- 平台特性：隐藏并恢复导入的日历事件。

### HarmonyOS

- ArkTS + ArkUI App、Form Kit 服务卡片、HarmonyOS Calendar Kit。
- 日历读写、后台代理提醒和服务卡片已接入，真实系统行为待真机回归。
- 历史忽略/恢复入口不属于当前范围，待清理。

### Android

- Kotlin + Jetpack Compose App、Glance/AppWidget 桌面组件、Calendar Provider。
- Android 13 及以上需要运行时通知权限；精确闹钟和后台调度受系统/OEM 限制。
- 日历、提醒、深链和组件已接入，真实系统行为待真机验收。
- 不提供导入事件隐藏/恢复。
- 应用内容避让系统安全区；桌面组件按宿主实际宽高和字体预算展示可完整容纳的事件，不固定中/大尺寸条数。

## 4. 验收要求

三端通用：

- 事件按剩余天数从近到远排序；今天、明天、后天文案正确。
- 年度事件按 `originalDate` 重算；2 月 29 日跳过非闰年；农历样例正确。
- 相同年度事件按规范化标题、类型、历法、月、日和闰月标识去重。
- 编辑或删除后，提醒取消旧任务并按新状态排程。
- 组件/卡片展示平台支持数量内最近的事件。
- 中文和英文跟随系统语言，不混用用户可见文案。
- 特别数字、深夜来信、长按揭示和到达庆祝满足频控、准确值、无声音和减少动态效果要求。
- 彩蛋不改变业务或系统状态。

iOS 专项：

- 导入事件可仅在 App 内隐藏，刷新后不重新显示，并可恢复。
- 从系统日历删除导入事件前显示明确确认提示。
